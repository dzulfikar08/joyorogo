# Announcement email (broadcast)

One-time mail to every user, from the admin console (`admin.joyorogo.com#email`). Code: `apps/server/src/broadcast*.ts`, `unsubscribe.ts`, `apps/admin/src/sections/Email.tsx`. No D1 migration.

- **Sender.** `BROADCAST_SENDER` in `broadcast-campaign.ts` (`Dzulfikar <dzulfikar@joyorogo.com>`), sent through the `EMAIL` binding with a `List-Unsubscribe` + `List-Unsubscribe-Post: List-Unsubscribe=One-Click` header. Transactional mail (receipts, digests) keeps using `EMAIL_FROM`.
- **Content.** Markdown subset in, HTML + text out (`broadcast-render.ts`): blank line = paragraph, `- ` list, `**bold**`, bare or `[x](url)` links, `{nama}` = first name ("kamu" if none). The unsubscribe footer is always appended. No images, no tracking. The console opens with `DEFAULT_CAMPAIGN`.
- **Recipients.** `user.email_verified = 1`, minus opt-outs. `user` has no banned/deleted flag (a deleted account has no row).
- **Once per user.** `email_log` row `kind = broadcast:<campaignId>`, `ref = <userId>`, claimed before the send on `UNIQUE(kind, ref)` and released when the send fails. Test sends are `broadcast_test:<campaignId>` (ref `<userId>:<ms>-<rand>`) and do not count.
- **Batches and resume.** Each call mails at most `BATCH_LIMIT` (40) users, 4 at a time, and stops at a rate-limit-looking error or 3 failures in a row. The first "Kirim ke semua" writes `email-broadcast/<id>.json` (STICKERS bucket) with the confirmed subject/body, status `sending`; the console repeats the call until nothing is left, and the `*/5` cron continues any campaign still `sending`. Re-clicking resumes and skips users already in `email_log`. A user whose send fails 3 times (not counting rate limits) is left out (`failed` in the status).
- **Opt-out.** `GET /unsubscribe?t=<token>` shows a confirm page, `POST` records `email-optout/<userId>` in the STICKERS bucket (browser button or RFC 8058 one-click). Token = `<userId>.<HMAC-SHA256(BETTER_AUTH_SECRET, "unsubscribe:v1:<userId>")>`, no expiry. Opt-outs are listed from R2 before every batch. They cover announcements only.
- **Endpoints** (`/api/admin/*` needs an `ADMIN_EMAILS` session): `GET /api/admin/broadcast`, `GET /api/admin/broadcast/status?id=`, `POST .../preview`, `POST .../test` (mails the signed-in admin), `POST .../send` (`{ id, subject, body, expected }`, first call must pass the confirmed recipient count). CLI, `X-Bench-Key: AI_BENCH_KEY`: `GET /ai/broadcast/status?id=`, `POST /ai/broadcast/test` (`{ to? }`, only to an `ADMIN_EMAILS` address that is also a user). Sending to everyone is console-only.
