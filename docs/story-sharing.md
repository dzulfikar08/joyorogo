# Story sharing

The share sheet behind every "Bagikan ke Story" button (scan result, beranda,
rekap, latihan summary, challenge, sticker). Same layout on web and native: a
card preview, a template switcher (photo, sticker, brand; photo only when the
story has one), "Pakai fotoku", and four targets.

| Target    | Web                                                                                  | Native                                                                                  |
| --------- | ------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------- |
| Instagram | `navigator.share({files})`; only on mobile browsers that can share files             | Direct Story composer with a Facebook App ID, otherwise Instagram's share target; hidden if the app is not installed |
| Copy      | `navigator.clipboard.write(ClipboardItem image/png)`, message where unsupported      | `expo-clipboard` `setImageAsync`                                                         |
| Save      | PNG download                                                                         | `expo-media-library` `Asset.create`, behind a pre-prompt with a "Lanjut" button          |
| More      | `navigator.share({files, text})`; only where the browser can share files             | `react-native-share` system sheet with the caption                                       |

Code: `apps/web/src/components/story/share-story-button.tsx`,
`apps/native/components/story/share-story-button.tsx` and `share.ts`. The card
painters (`story-card`) are unchanged. The Instagram glyph is
`packages/api/src/lib/instagram-glyph.ts` (source and terms in the file).

## Instagram on native: with and without the Facebook App ID

`EXPO_PUBLIC_FB_APP_ID` is read by `instagramFbAppId()` in `share.ts`.

**With an ID** (release builds set it): `Share.shareSingle` with
`Social.InstagramStories` opens Instagram's Story composer directly
(`com.instagram.share.ADD_TO_STORY` on Android, `instagram-stories://` on iOS)
and passes the ID as `source_application`. The transparent sticker template goes
in as `stickerImage`, so it lands as a movable overlay on the user's own
camera shot or photo; photo and brand render as the full-bleed
`backgroundImage`. No gallery permission is needed.

**Without an ID** the direct route is not allowed, so the PNG goes through
`Social.Instagram`:

- Android: Instagram's own chooser (Feed or Your Story) with the image. The
  sticker arrives as a flat image, not an overlay.
- iOS: the plugin saves a JPEG to the photo library and opens it in Instagram's
  composer. It needs full photo access, so the app asks first behind the styled
  pre-prompt. If access is refused or limited, or the hand-off fails, the system
  share sheet opens instead. A JPEG has no transparency, so the sticker loses it.

Any failure on either path falls back to the system share sheet; a cancelled
share is not an error.

Detection: Android `Share.isPackageInstalled('com.instagram.android')` (needs the
`<queries>` entry), iOS `Linking.canOpenURL('instagram://')` (needs
`LSApplicationQueriesSchemes`). Both are generated by the `react-native-share`
plugin entry in `app.json`.

## Permissions

Save asks for write-only photo access: iOS add-only (`NSPhotoLibraryAddUsageDescription`
from the `expo-media-library` plugin entry), Android below 13 `WRITE_EXTERNAL_STORAGE`.
Android 13+ writes through MediaStore without any permission, so nothing is asked
and no `READ_MEDIA_*` permission is declared (`granularPermissions: []`, and
`READ_MEDIA_VISUAL_USER_SELECTED` is blocked in `app.json`).

The pre-prompt button reads "Lanjut" / "Continue"; the system dialog only follows
it. When the system already refused, the sheet explains and offers "Buka
Pengaturan".

The sheet is a Modal that covers the toast layer, so a successful Copy or Save
closes it and then shows the toast; failures stay inline with a retry button.
